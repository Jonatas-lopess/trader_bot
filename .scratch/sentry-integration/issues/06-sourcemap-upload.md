# 06: Source-map upload on deploy

**Split from:** 04 (dashboard-readability follow-up split into two independent tickets — see
04's Comments).

**Category:** enhancement

**What to build:** any real deploy (even the workers.dev test route, not just a future
production one) ships the Vite-bundled `dist/server/entry.mjs` and its chunks — minified,
renamed. A captured exception's stack trace in the Sentry dashboard currently resolves to
that renamed chunk output (confirmed on ticket 01's verification event:
`Module.GET(debug-sentry_BLY-NfUD.mjs)`), not original `file:line`. Needs a source-map upload
step (Sentry's Vite plugin or CLI) wired into the build, plus a Sentry auth-token secret
available wherever that upload runs.

**Blocked by:** 01 (done — the wrapper this ticket's dashboard evidence came from)

**Status:** done — `SENTRY_AUTH_TOKEN` set on the "dev" Environment, CI upload confirmed working

**Why this needs a human, not just an agent:** creating the Sentry auth token requires
signing into the Sentry dashboard (Settings → Auth Tokens, `project:releases` scope) —
external access an AFK agent doesn't have — and then adding it as a secret to wherever CI
runs (GitHub Actions repo/environment secrets). The build-side wiring (Vite plugin config,
release/version naming, upload step in the pipeline) is ordinary code and can be delegated to
an agent once the token exists; do that as a follow-up ticket, or as a second pass on this one
with the token supplied as a working secret name.

## Answer

Build-side wiring is in, gated on `SENTRY_AUTH_TOKEN` so builds without it (CI's build/test
job, local) are unchanged:

- `astro.config.mjs`: `@sentry/vite-plugin` + `build.sourcemap` only when the token is set;
  release name = `SENTRY_RELEASE`; only `dist/client` maps are deleted after upload (they
  would be served as public static assets). Server maps stay: `entry.mjs` references
  `entry.mjs.map` and `wrangler deploy` rejects a dangling reference.
- `.github/workflows/ci.yml`: deploy job's Build step gets the token and release;
  the Deploy step passes `--var SENTRY_RELEASE:<sha>` (`@sentry/cloudflare` reads it off the
  env, so events carry the release the maps were uploaded under).
- `pnpm-workspace.yaml`: `@sentry/cli: true` in `allowBuilds` (its install script fetches the
  upload binary).

**Human steps remaining (nothing uploads from CI until this is done):**

1. Token: already created via `npx @sentry/wizard -i sourcemaps` (local copy in the gitignored
   `.env.sentry-build-plugin`). Org `jonatas-lopes` / project `trader-bot-worker` are
   hardcoded in `astro.config.mjs` (slugs, not secret).
2. GitHub → Settings → Environments → **dev**: add secret `SENTRY_AUTH_TOKEN` (same value).
3. Push to main; trigger an error on the workers.dev route and confirm the stack trace shows
   original `file:line` instead of `Module.GET(debug-sentry_*.mjs)`.
