## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Sentry-captured events should carry an `environment` tag that reflects which
deploy they came from, instead of Sentry's `"production"` default.

**Current behavior:** the Sentry client initialization options passed to the error-capture
wrapper don't set `environment`. Every captured event — from the workers.dev test route, from
local dev with a DSN bound, from any future production deploy — is tagged `"production"` in
the Sentry dashboard.

**Desired behavior:** the `environment` tag on a captured event reflects where that Worker
instance is actually running. At minimum, the workers.dev test-phase deploy must not read as
`"production"` in the dashboard. The distinguishing value should be sourced the same way this
repo already sources other per-deploy configuration (env binding or `wrangler.jsonc`
per-environment var — follow whatever precedent the existing Sentry DSN binding or other
provider config already sets), not hardcoded into a shared config file that's identical
across deploys.

**Key interfaces:**
- Wherever `Sentry.withSentry`'s (or equivalent) initialization options are constructed: add
  an `environment` field, sourced per-request off an env binding the same way `dsn` already
  is (not module-load time, not hardcoded).
- Whatever value distinguishes "workers.dev test route" from "not yet deployed" (no DSN
  bound, so moot) from "a real production deploy" once one exists.

**Acceptance criteria:**
- [ ] A captured event from the current (workers.dev test route) deploy does not tag
      `environment: "production"` in the Sentry dashboard
- [ ] The value is read per-request off env/config, not hardcoded at module load
- [ ] `pnpm test` and `pnpm run typecheck` pass
- [ ] PLANNING.md's stack/config table gets a row if this introduces a new env var or
      `wrangler.jsonc` var (mirror however ticket 01 recorded `SENTRY_DSN`)

**Out of scope:**
- Source-map upload (ticket 06 — separate blocker, needs a human-provisioned credential)
- Defining what production's `environment` value will be before production itself exists;
  just make sure the test-phase deploy isn't lying about being production
